Case Study · 2024 — Present

Designing the platform behind 50-state policy intelligence.

Two years of work at State Affairs — a B2B legislative tracking platform used by enterprise teams to monitor policy across all fifty US states. Below: the features I shipped, the tools I scaled nationwide, and the systems work behind both.

TL;DR

Senior product designer leading UX for State Affairs, the legislative intelligence platform used by lobbyists, advocacy teams, and government affairs professionals to track policy across all 50 state legislatures. Drove the redesign of six core surfaces — including 360-degree bill views, the directories system, search/keywords, and the live voting scorecard — as the platform scaled from a regional tool to a national one. Worked across product, engineering, and customer success to ship features that turned messy public-record data into something teams could actually act on.

— 01 / Reference & Search

Code Annotated, scaled from one state to fifty.

Taking a state-specific tool and rebuilding it as a platform-wide capability.

Role Lead designer
Surface Desktop · Mobile web · Native mobile
Year 2024

Code Annotated started as a Tennessee-only legislative reference tool. The work was to take it nationwide — preserving what made it useful at the state level while introducing the structure needed to scale across fifty distinct legal codes.

The problem

Each state codifies its laws differently — different titles, different chapter numbering, different relationships between sections and the bills that reference them. A flat list wouldn't survive that variance, and a single state-specific UI couldn't either.

The design

I designed a branch-style interface that breaks each state's code down by title, then chapter, then section, with referenced bills surfaced at every level. Users can follow specific sections to receive alerts when new bills cite them — which is the actual reason this feature exists for power users.

Code Annotated — Title view
Fig. 01 Title-level navigation showing chapters with associated bill counts.

Scaling across surfaces

The same hierarchy had to work on desktop, mobile web, and native mobile. The branch metaphor held up across all three because it's structural rather than visual — each surface expresses the depth differently, but the model underneath is identical.

— 02 / Bill Tracking

Document Comparison, the first cross-state legislative diff tool.

A standalone capability that didn't exist anywhere in the industry.

Role Lead designer
Distinction Industry-first capability
Year 2024

Comparison tools existed in legislative software, but only inside a single bill — version A versus version B of the same legislation. State Affairs became the first platform to let users compare any two documents from any two bills, anywhere in the country.

Why this is harder than it sounds

Cross-bill comparison breaks the assumption that gives most diff tools their structure: that the documents share a parent. Without that, the search experience is doing more work than the diff itself — users need to find document B with no implicit context from document A.

The design

I built a two-panel selector with independent search on each side, document-type filtering (fiscal notes, amendments, proposed versions), and clear empty states for each panel until two documents were chosen. The comparison itself runs after both are selected.

Document Comparison — Selection state
Fig. 02 Two-panel selection with independent search and type filtering.

The pattern set the standard other features have followed since — the same two-panel selection structure now appears across cross-cutting tools elsewhere in the platform.

— 03 / Keyword Alerts

Untangling a fragmented save-and-search experience.

A redesign of the platform's most actively-used power-user feature.

Role Lead designer
Status Stakeholder review
Year 2025

Keyword Alerts had grown into the most actively-used feature on the platform — and also the most fragmented. Saving, editing, organizing, and searching had each evolved separately, with overlapping interactions and inconsistent results across content types.

What I changed

  • Redesigned card patterns across four content types — news, hearings, legislators, committees — so results feel coherent regardless of what's matching.
  • Rationalized search modes into three named options: Quick search, Phrase builder, and Boolean. Each surfaces different controls instead of competing for the same input.
  • Consolidated the save and edit experience into a single creation drawer. Previously these were two separate flows that diverged in subtle ways.
  • Rebuilt folder creation as an inline dropdown, removing a modal that was interrupting the most common save path.

— 04 / Voting Scorecard

An empty state that holds the room before the data arrives.

Designing for the long pre-vote stretch most scorecard tools ignore.

Role Lead designer
Type Craft / Empty states
Year 2024

Voting Scorecards spend most of their lives empty. Bills sit on the floor for weeks before votes are recorded, and during that stretch users still need the page to feel like a tool — not a broken view of one.

The design

Ghost columns in a muted state hold the structure of the eventual scorecard, paired with a footer banner that explains the state plainly. When every bill is pre-vote, a distinct all-empty body state takes over rather than repeating the per-column treatment dozens of times across the table.

Scorecard — Pre-vote ghost state
Fig. 04 Ghost columns with footer banner explaining the state.

Small surface, but a real call: power users wanted hand-holding at this stage, and stripping the table to a single message would have hidden the structure they were trying to read into.

— 05 / News

Bringing editorial weight to a B2B reading surface.

A typographic refresh of the platform's news experience.

Role Lead designer
Type Visual refresh
Year 2025

State Affairs publishes original statehouse reporting alongside its tracking tools. The news surface had been styled as a B2B feed — the visual language closer to a dashboard than to the journalism it housed.

I reset the type system around editorial fundamentals: a serif headline face for hierarchy, a serif body face tuned for long-form reading, and a tighter color palette that lets the writing carry the page. The structure stayed consistent with the rest of the platform; the surface around it changed.

— 06 / 360 Views

The collaboration layer inside the flagship.

Comments and detail panels across State Affairs' bill workspace.

Role Designer · Comments & detail panels
Surface 360 Views
Year 2025

360 Views is State Affairs' bill workspace — the surface where teams analyze, annotate, and act on legislation together. I owned the comments and detail panel layer that lives across it.

The data model decision

The first design question was scope: should comments live on the bill, or per-view inside it? After prototyping both, the team landed on bill-level comments with view filtering — one source of truth, with the comments filtered to whichever view a user is reading them in. The data model reads cleanly across the whole feature; the UI can vary per surface without forking.

Two prototypes, one decision

For the bill detail panel I built two variants: one where 360 view threads expand inline, and one with compact link-out rows. The toggle was a native HTML details element rather than a custom component — proving the interaction without committing the engineering team to a pattern that hadn't been validated yet.
